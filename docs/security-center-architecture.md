# APPGOG 三中心安全架构与验收方案

状态：设计基线（2026-10-01）。本文定义目标和验收门槛；未完成的能力不得在面板上显示为“已防护”。

## 1. 目标、资产与信任边界

保护授权数据库、签名密钥、客户和产品源包、构建产物、发布链、业务机 Linux 宿主机，以及云端留存的基线与事件。支持 A：授权和打包同机、云端独立；B：三中心各一机。每台业务机部署自己的安全代理。云端只接受已配对节点上报、进行外部健康探测、保存独立基线及事件。Cloudflare 账号、会话、API 令牌和 DNS 变更独立监控；服务器查杀不能给 Cloudflare 失陷兜底。

威胁：被盗的后台会话、受损业务容器、业务机宿主机、被污染的构建产物、云端安全机失守、发布密钥失守、凭据泄露、断网、误报和恶意回滚。保护边界明确：同机容器隔离不能抵御宿主机 root；业务进程生成的遥测可能被其控制者伪造。不得宣传“绝对杜绝入侵”。

## 2. 组件和权限

| 组件 | 允许 | 禁止 |
|---|---|---|
| 授权后台 | `system.manage` 管理员在 CSRF 与限流检查后发起固定扫描、读取脱敏报告 | 浏览器提供文件路径、命令、Docker/SSH 凭据 |
| 本机安全代理 | 主机上按固定规则只读扫描、缓存报告、主动上报云端 | 执行来自浏览器/云端的任意命令、自动更改发布基线 |
| 打包节点代理 | 检查打包相关路径，使用 build 身份上报 | 持有云端 reader、授权签名密钥或授权数据库 |
| 云端中心 | 通过 mTLS 和独立令牌识别 license/build/reader、独立健康探测和留存证据 | SSH 到业务机、访问 Docker API、保存发布签名私钥 |
| 发布系统 | 在隔离发布环境签名，经 CI 与合同验收发正式版本 | 从受怀疑的生产机自动生成可信基线 |

业务容器保持非 root、只读根文件系统、最小权限和无 Docker socket。安全代理使用单用途 Unix socket；业务容器即使控制该 socket，也只能触发有频率限制的固定扫描并读取脱敏报告。代理的检查配置由本机管理员管理。网络白名单以真实业务调用方向和端口确定，不能假设授权与打包之间无需通信。

## 3. 检测层

**本机一键检查**：异步返回任务状态；扫描 Linux 发行版、内核、重启需求、安全更新状态、监听端口、SSH 账号和配置风险、systemd/cron 持久化、服务状态、文件与目录权限、业务代码完整性，以及可选的 ClamAV 病毒特征扫描。每项返回 `ok/warning/finding/unavailable`、时间、范围、原因和脱敏证据。未安装依赖或无读取权限显示 `unavailable`，不得算作通过。扫描受限于文件、耗时和输出上限，不读取或回传密钥和业务数据。

**持续监测**：节点定期上报受控代码目录摘要，云端独立核对经过正式发布验证的基线并做外部 HTTPS 探测。高风险 Linux 事件和登录审计独立转发；云端存储应单独备份，定期验证恢复。基线只在验签、发布记录和人工复核后更新。

**结论区分**：本机检查、云端核验、病毒特征扫描、连通性与探测分别显示；断线、过期、未配置和检查失败都是“未知/异常”，不能包装成健康。恶意特征扫描未命中也不等于未入侵。

## 4. 分级响应

- L0：配置差异或单项文件变化，保存证据并复核发布记录，不自动清理。
- L1：关键文件偏移、异常持久化或可疑进程；禁止新的高风险构建/交付并通知管理员，保留服务与证据。
- L2：多个独立证据确认正在入侵；由本机独立控制通道只隔离受影响服务，记录原状态、隔离期限与撤销步骤。恢复从已验签、已核对摘要和数据兼容的版本进行。
- L3：授权中心或云端失守；各节点停止信任失守方的新策略与产物，继续本地检查和告警；从独立管理通道吊销相应凭据、取证和重建。云端不能直接推送执行命令。

任何自动动作先写可审计事件，明确触发证据和回滚条件。单次哈希变化或三次探测失败只能触发复核/降级，不盲删容器、不固定封锁流量、不覆盖数据。Linux 安全代理不触及数据库和业务数据卷的删除。

## 5. 更新与离线生存

两套安装器识别发行版、架构、包管理器和已有配置；只补齐受支持的依赖，先备份后升级，健康检查失败恢复上一个健康版本，保留数据库、密钥、产物和日志。若发行版、架构或服务管理器不受支持，明确失败，不执行猜测安装。业务和安全云端各自签发独立身份，轮换分 stage/验证/commit。断网时本地监测和留证继续，暂停远端更新；缓存恢复版本须验签、核对摘要和数据库兼容性。正式产物的签名私钥只在隔离发布环境，业务节点本地校验公钥及内容摘要。

## 6. 面板与接口合同

授权中心“安全查杀中心”增加本机 Linux 状态卡、“一键检查本机”及任务进度与逐项结果；云端状态保持独立。`POST /web/admin/security/local-scan` 仅具备 system.manage 的管理员可用，检查 CSRF、限流和审计，返回 202/任务；`GET /web/admin/security/local-scan` 返回本机代理的脱敏状态。面板不允许提交任意扫描路径、命令或清理策略。失去本机代理时显式显示不可用；不影响原有云端状态查询。生产代理使用不对公网开放的 Unix socket。

## 7. 验证门槛

1. 单元与接口：权限/CSRF、限流、恶意路径与请求体拒绝、并发扫描与超时、扫描器不可用、脱敏、旧安装无代理时正确显示。
2. Linux 集成：apt/dnf 系统首装与升级、同机/三机角色、systemd 代理启动和重启、socket 权限、无云端的本机扫描、文件偏移、病毒特征测试文件、断线恢复。
3. 对抗演练：授权进程遭劫持不能获取 Docker socket/云端私钥；云端证书、令牌、CA、身份和域名不符均拒绝；云端放置未签名产物拒绝使用；误报撤销不丢数据。
4. 发布：全量测试、Shell 语法、发布合同、签名附件、GitHub Ubuntu/Docker CI、真实服务器首装/升级/备份恢复与网络连通性；每项记录证据，未通过不能标记生产验收。

实施顺序：先本机只读扫描与面板真实接口，再增加主机侧持续审计及与云端核对，随后实现策略化隔离、签名恢复和全拓扑演练。任何页面“预览”文案必须与实际可用能力相符。
