# APPGOG打包授权系统 v1.2.41

## 修复范围

- 授权桥升级为 1.1.1。常驻 PHP 进程保留旧响应监听器时，插件文件缺失或自动加载失败不再破坏原生后台的正常响应；主路由本身的异常继续传播。
- 持久化宿主守卫的后台脚本装饰失败时保留原生恢复入口。受保护主题的读写、启用、签名、域名、安装身份和撤销检查不变。
- 识别“激活主题”等原生按钮文案，先打开本地激活窗口再继续两阶段流程。避免克隆删除图标样式；已启用主题的授权入口放在设置按钮旁。
- 新增唯一迁移 2026_09_27_000008_admin_recovery：同步覆盖持久化 Guard 和 admin-entry 脚本，安排提交后的进程重载，保留身份、激活、登记和原始 bootstrap 备份。

## 验证与边界

- PHP 回归覆盖删除插件资源、失效自动加载器、原生路由异常、旧宿主副本升级及重复迁移；授权拒绝用例继续执行。
- 浏览器卡片回归脚本 `scripts/verify-bridge-admin-ui.cjs` 覆盖删除按钮在先、“激活主题”、当前主题、按钮位置及禁止提前发送启用请求。
- Node、Docker、Caddy 与环境合同不变。
- 更新运营/打包中心不会自动替换各客户服务器已经安装的插件。客户需升级授权桥到 1.1.1 并确认运行时健康版本；已无法打开后台的服务器先按 `docs/xboard-admin-recovery.md` 取证和恢复。
- 这次修复针对已在本地复现的缺陷；没有取得客户服务器应用异常堆栈时，不能宣称已确定所有 Internal server error 的原因。
