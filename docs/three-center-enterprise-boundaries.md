# 三中心部署、安全与恢复边界（候选实施，2026-10-01）

## 目标与部署形态

| 形态 | 业务服务器 | 独立安全服务器 | 安装角色 |
|---|---|---|---|
| A 同机 | 授权、打包及构建在同一台 | 云端监测一台 | 业务 `--role all`，云端独立安装 |
| B 分机 | 授权一台、打包与构建一台 | 云端监测第三台 | 业务 `--role license` 与 `--role build` 分别安装，云端独立安装 |

两种形态使用同一套业务源码、相同的签名正式发布合同；不得在已有数据上原地改部署角色。授权机拥有授权数据库和业务签名密钥，打包机只有单独签发的打包与 Worker 节点凭据。云端仓库独立，不持有业务机 SSH、Docker socket、授权密钥、发布签名私钥；打包机不持有云端 reader 身份。域名各自解析到对应业务机。受支持范围是安装器明确识别的 Linux、架构、包管理器和服务管理器；“万能”指在受支持环境自动补依赖，不能承诺任意发行版、内核和硬件。

## 已实现的入口和信任边界

- 业务安装器默认 `all`，分机分别使用 `license`、`build`；打包首装须输入授权中心分别签发的两个节点凭据文件。正式首装由签名发布入口获取源码；候选测试可用本地经核验源码。安装后的 `appgog` 管理菜单 17 或 `security-local status|scan` 可操作本机 systemd 代理。代理扫描是固定范围、限频、只读；缺失、过期、不可用和告警不能显示为“已安全”。病毒特征扫描仅是其中一项，不证明不存在入侵。
- 本机代理固定检查发布文件基线、受控文件清单的 ClamAV 结果、唯一 APPGOG 主容器的镜像/用户/健康/只读根文件系统/Capability/挂载合同、SSH 实际生效配置、固定敏感文件权限以及内核 TCP/TCP6 监听姿态。每项证据使用有界字段和确定性 SHA-256 摘要；代理不读取密钥内容，也不接受浏览器提供命令、路径或策略。当前实现只报告和留证，不会自动停止容器、断网、删除文件、修改 SSH/防火墙或执行恢复。
- 每台业务机 `appgog security-connect URL BUNDLE_DIR CA_SHA256` 配对独立云端。云端控制台单独传递 CA 指纹，业务机在写入任何身份材料之前比对指纹；已有 CA 变化时拒绝自动替换。通信使用服务端证书校验、按角色的客户端证书和独立令牌；授权机持 reader/license，打包机仅 build。`security-doctor` 检查身份、报告新鲜度与云端状态，分机授权侧的汇总结论以两个业务角色都健康为准。
- 首次“锁定”是固定云端 CA 和角色身份。普通断线使远端结论变为不可用，不锁死本地菜单、扫描、备份或带外管理。换证走云端 stage、业务端验证、云端 commit；换 CA、云端失守或最高权限沦陷须离线核实、吊销和重建。没有把万能解锁密钥放入代码、命令行或业务机。仅靠软件内一个“特殊密钥”无法阻止已获宿主 root 的攻击者篡改同机程序和状态。
- 安全云端独立仓库支持从已认证的私有 Git 源安装；README 给出一条命令：安装 Git、按预审提交 SHA 获取源码、执行现有安装器。SSH deploy key、可信主机指纹和预审 SHA 是必须预先由独立渠道提供的信任材料。安装器补齐支持环境依赖，配置 systemd 并检查本机 HTTPS 身份。云端没有业务机远程执行能力。

## 防护等级与响应

1. 单项偏移：留存原始时间、路径摘要和版本信息，停止把该项报告为健康，复核发布变更和可能误报。不得立刻删容器或覆盖数据。
2. 多项独立证据：由**业务机本地**受限控制通道冻结受影响的高风险构建和签发操作，保留证据、记录触发与解除条件。当前候选尚无经过实机验收的自动冻结控制器，不得在 UI 中显示为已生效。
3. 授权中心失守：云端保留独立外部探测和历史基线，打包机停止信任受损授权凭据的新增高风险请求；从可信控制台吊销身份、核验授权数据库和签发记录，从干净版本/备份重建。云端报告不能独立证明已经取得 root 的业务机干净。
4. 云端失守：业务机停止接受云端新策略、基线和更新，仅保留本地受控检查；离线重建云端、换 CA 和节点证书。由于云端没有 SSH/Docker 权限，它不能直接发命令，但泄露的身份材料和虚假报告仍须按事故处理。
5. 失联：本地扫描与留证继续，远端显示过期；不进行盲删除、盲回滚或自动提升备用主。恢复时验证证书、时钟、身份和报告新鲜度。

## 数据、发布与容灾

- 业务安装/升级保留 `.env`、数据卷、签名密钥、客户包和备份；发布源须验证签名和 SHA-256。云端版本目录与配置状态分开，同版本不同源码拒绝覆盖。临时安装源码的 Git SHA 固定不是生产签名发布的替代品；云端正式独立签名 Release 及回下载验收仍需建设。
- 现有人工加密备份与空机恢复可作为冷备。异地不可变副本、备份验真、独立长期审计、单写入围栏、RPO/RTO 实测及自动恢复控制器尚未实现。两机/三机、证书轮换、云端断线、误报撤销、故障恢复和旧主重上线均需真实 Linux 演练。
- Cloudflare 账号与 DNS 劫持独立于这三个服务器的文件扫描；必须由账号多因素认证、最小权限令牌、变更审计和带外 DNS 校验处置。不能把业务节点的“查杀通过”解释为 Cloudflare 安全。

## 上线判定

候选代码通过本地测试与 CI，只证明受测合同。正式发布还须遵守仓库 `AGENTS.md` 的版本递增、签名制品、main CI、回下载验证；生产启用另需记录主机身份、部署版本、节点双向认证、负面认证测试、备份恢复、断线和失守演练。缺任何一项，状态维持“未验收”，不宣传杜绝入侵或整体完成。
## 可执行的角色与控制矩阵

| 身份 | 持有的凭据 | 可做的操作 | 明确禁止 |
|---|---|---|---|
| 授权机 | 业务签名密钥、授权数据、云端 `license` 和 `reader` 身份 | 签发授权、查看双节点汇总、上报本机状态 | 远程执行打包机或云端命令 |
| 打包机 | 独立的 `build-center`、`worker` 节点凭据及云端 `build` 身份 | 构建、向授权服务取受约束的授权结果、上报本机状态 | 读取授权数据库、云端汇总身份和签名私钥 |
| 独立云端 | 单独 CA、节点身份登记、可信发布基线及上报历史 | 核验身份、接收报告、外部探测、告警与身份轮换 | 业务机 SSH、Docker socket、数据库写入和远程命令 |
| 带外管理员 | 独立保存的 CA 指纹、恢复材料和发布验签公钥 | 首次信任确认、失守复核、吊销和灾难恢复 | 将永久通用解锁密钥放进业务机或网页 |

接口规则：业务节点主动使用 HTTPS/mTLS 连接云端，客户端证书再绑定角色令牌；云端对授权和打包的外部 HTTPS 健康端点做独立探测。每次报告必须包含格式为 `YYYY-MM-DDTHH:mm:ss.sssZ` 的 UTC `observed_at` 和随机 UUIDv4 `report_id`；有效期为 120 秒，未来时钟偏差最多 60 秒。云端按节点持久化最近 256 个 ID，服务重启后仍拒绝窗口内的重复 ID；拒绝必须发生在完整性、宿主扫描、新鲜度和审计状态变更前。该有界防重放合同要求业务节点维持可靠 UTC 时钟。云端不能通过上报通道下发任意 Shell、Docker 命令、脚本或未验签镜像。业务侧不以浏览器页面或云端单一报告作为最高权限授权依据；所有变更记录操作者、时间、目标角色和结果。

## 安装、回退和验收合同

1. 先分别在干净的受支持 Linux 上测试同机 `all`、分机 `license` 和 `build` 的首装、重复安装、升级、备份和恢复；同一台机器已有角色时，原地换角色必须拒绝。打包首装需要授权侧单独颁发的节点凭据。独立云端使用其私有仓库的一行受信提交安装入口；只读仓库身份、可信 SSH 主机密钥与已审查提交 SHA 预先带外就绪。
2. 云端登记两角色并建立经正式发布验签的基线，再按角色私密交付身份包。每台业务机首次输入独立获取的 CA SHA-256 指纹；拒绝空指纹、错误指纹、替换 CA、错误身份、错误令牌、错误域名和过期证书，并证明拒绝时原运行配置未改变。配对重启应安排维护窗口。
3. 本地检查须报告扫描范围、引擎状态、时间和每项结论。超时、扫描未结束、引擎缺失、基线失效或上报过期一律显示未知或异常。手工/自动扫描共用冷却与锁。云端断线不阻断本机只读检查和人工恢复；恢复后对时钟、证书、身份、报告时间戳和历史基线重新核验。管理 API 只接受固定 `status`/`scan` 动作并连接固定本机 Unix Socket；响应最多 32 KiB、最多 20 项。`id`、类别、严重度、检查时间、范围和证据摘要经过严格白名单、长度与格式验证后才进入后台，代理返回的额外字段不会透传。
4. 执行失守桌面演练：授权机失守、打包机失守、云端失守、Cloudflare/DNS 被改、假阳性、备份损坏、双节点失联及旧主复活。冻结与恢复必须由业务机受限控制器和带外管理员共同核验；不得用网络失联触发盲删数据。证明备份能从隔离环境恢复，记录实际 RPO/RTO、单写入围栏和证据保存。
5. 发布验收按签名清单、SHA-256、正式 Release 回下载以及 Ubuntu/Docker CI 的同一提交证据进行。当前候选通过测试不等于已上线；生产还需主机身份、证书和权限审计、真实 systemd/ClamAV 与两/三机认证、升级回滚和恢复演练记录。

后续优先级：先增加独立备份和不可变异地副本及恢复演练，再做只冻结高风险写操作的本地控制器与人工解封流程，最后考虑自动容器重建。每一级都以最小权限、可撤销、幂等和误报恢复为上线门槛；云端独立签名发布仍需建设，私有仓库的固定 SHA 只能标识源码提交。

## 本地优先候选实现与边界

本地代理每五分钟检查一次，后台提供手工检查与最近八条状态变化，本机最多保留六十四条。手工和定时扫描共用冷却及锁。程序清单覆盖 apps、packages、scripts 与发布根合同文件；依赖、上传、数据库、构建成品和宿主机其他目录不在病毒扫描范围。主机配置基线另行覆盖账户、SSH、sudo、cron、systemd、Docker 与防火墙配置。TCP/TCP6 监听及 Docker 容器合同为只读检查。结果只说明已检查的范围。

三种部署角色共用本机安装器及专用 Socket 组。安装补齐 ClamAV 和特征库自动更新；软件源或下载失败时保留业务，查杀明确显示不可用，可从 Linux 菜单重试。程序和主机基线由 root 在核验可信版本或合法变更后分别批准，重复安装不会接受未知变更。管理菜单加载或执行脚本前校验 root 所有权及父目录不可被其他用户写入。

此候选完成检测、后台告警、历史及菜单接入，尚未实现文件自动隔离、可信修复和恢复闭环，也未完成生产环境整机验收。后续处置需保护业务数据、留存证据、可撤销，并通过真实 Linux 演练。
