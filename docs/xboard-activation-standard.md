# Xboard 主题激活与宿主保护标准

适用：平台 v1.2.40 起、授权桥 1.1.0 起新构建的客户主题包。

## 固定操作流程

1. 已完成宿主接入的 Xboard 上传受保护主题 ZIP。宿主准备静态激活入口，尚不启用主题；上传后弹窗准备/升级授权桥，明确显示结果。
2. 点击主题卡片的激活按钮，先打开本地 Install Key 弹窗。点击开始激活后启用原有 60 分钟安装窗口；输入错误不得启用主题，也不得重置窗口。
3. 本地安装 Key 验证成功后关闭弹窗并跳转主题 editor.html，在整页在线激活界面输入长期 License Key。后台安全路径从原生管理员会话继承。
4. 在线激活签名、域名和安装身份验证成功，状态保存到授权桥后才启用主题。
5. 正常后台中的“授权与更新”作为右侧主内容区，不是弹窗；客户访问页不提供后台管理菜单。
6. 组件缺失、停用、凭证失效时，后台与预览一致锁定。原生 Xboard 管理入口保留，用于恢复组件。

## 首次接入前提

静态主题 ZIP 本身不能在从未接入的 Xboard 上执行插件安装代码。首次必须通过 Xboard 官方插件上传/安装入口安装并启用授权桥一次，并重载应用。之后受保护主题上传和激活使用自动准备流程。不能把“零宿主集成、任意 ZIP 上传即执行 PHP”描述为受支持能力。

桥安装/迁移将固定模板 Guard.php 和后台入口脚本存放于 `storage/app/private/appgog-host`，向 `bootstrap/app.php` 注册中间件。首次写入前备份完整原文件为 `bootstrap-original.php`，保留文件权限，原子替换；不支持的 bootstrap 结构必须拒绝，不猜测修改。首次安装及升级需要 bootstrap 和私有存储可写、PHP Sodium 可用。

插件删除不会删除此守卫、安装身份或授权状态。原生后台能继续登录、安装插件和切换其他主题。不得把删除数据库或更换安装密钥作为修复步骤。

## 服务端边界与兼容

新包携带用途隔离的 Activation/Package 验签公钥；认证后的注册/上传固定保存公钥，签名包身份和激活凭证必须匹配。主题读取、保存、启用分别校验对应套餐能力。

旧包没有这些验证信息，桥升级时维持其原有运行规则；重新构建和安装新包后才进入宿主守卫保护。对已登记保护的主题，即使清单被删除，也不允许退回未保护状态。

浏览器定时复查用于及时锁定界面，不是服务端授权边界。已签发凭证的有效期与离线宽限仍按既有授权合同处理；授权中心撤销经刷新写回本地后立即锁定，不能宣称断网时即时获知远端撤销。

Xboard 核心更新如果整体替换 bootstrap，必须在开放服务前重新执行宿主接入并验证直接读取/保存拒绝场景。服务器所有者有权限删除守卫或修改核心代码，不能承诺对此绝对防绕过。静态 editor.html 可被 Web 服务器返回，但没有有效授权不能读取或保存受保护配置。

## 验收要求

- 未激活直接调用启用或保存 API 返回 423；本地激活完成但在线未激活也不得放行。
- 插件停用、删除文件、撤销状态、错误签名、过期、跨域、错误 Installation ID 均拒绝。
- 原生恢复入口、其他主题、合法旧包升级不受误伤。
- 429/5xx 保留原状态，给出可重试错误，不删除主题，不重复安装风暴。
- 新包三个入口均注入同一运行时；成品校验、一次性安装 Key 和固定 Key 语义保持。
- 对比升级前后管理员、授权、设置、安装身份和既有构建记录；必须保留。
