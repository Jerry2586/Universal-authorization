# APPGOG打包授权系统 v1.2.0

发布日期：2026-09-24。

## 管理后台与客户中心

- 公告中心成为独立功能，公告直接发布到客户打包中心。
- 授权 Key 不提供删除；新签发和轮换的完整 Key 加密保存，仅平台所有者重新验证密码后可查看，查看操作写入审计且不记录明文。
- 管理员可在用户中心修改密码；普通管理员账号支持软删除，平台所有者受保护；新账号初始密码固定为六位数字。
- 主题 ZIP 支持点击和拖拽真实上传，版本号与版本名称可从安装包自动识别。
- 版本目录移入客户“构建任务”，工作台只保留概览和最近构建；域名换绑不再要求说明。
- 系统与节点页增加在线检查、立即更新、修复当前版本和独立更新日志。
- 重写版本目录、公告编辑、更新状态和移动端构建任务界面，移除重复或无效入口。

## 安装、更新与数据保护

- Linux 安装目录改为 `releases/<版本>`、`current`、`shared` 三层结构；每次更新完整覆盖程序文件，不把旧源码合并进新版本。
- `.env`、日志和备份保存在 `shared`，SQLite、Key、上传、构建成品和证书继续保存在 Docker 数据卷，更新不会重置用户和运营设置。
- 部署通过原子链接切换；构建或健康检查失败时恢复旧程序与服务。
- 后台在线更新通过受限宿主机助手执行，只接受检查更新、安装版本和修复当前版本三种签名动作，不暴露 Docker Socket。
- `appgog update` 安装签名 Release；新增 `appgog repair-source` 和保留全部业务数据的 `appgog uninstall`。
- 同一条一键命令继续同时用于首次安装和跨版本升级，并保留 GitHub 代理、国内发布源与离线 `.run` 安装方式。

## 验证

- 全量 Node 自动测试通过，覆盖授权、Key 恢复权限与审计、公告、版本识别、构建、激活、部署保护和更新白名单。
- 发布 ZIP、`.run`、SHA-256、清单和清单签名由发布私钥重新生成。
