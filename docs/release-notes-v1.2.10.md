# APPGOG打包授权系统 v1.2.10

状态：候选版本，完成全部验证并通过 GitHub CI 后发布  
记录日期：2026-09-24

## 本次版本目标

v1.2.10 把授权、打包、工单、在线更新和服务器迁移按公司级边界完成一次兼容性重构。升级会完整覆盖程序源码、前后端、Docker 配置和安装脚本，但保留数据库、管理员账号密码、License Key、公告与运营设置、上传、构建成品、日志、备份以及全部签名和加密密钥。

## 安全与授权

- 激活、安装包和版本通知改用三套独立 Ed25519 密钥：Activation Signing Key、Package Signing Key、Notification Signing Key。
- 旧部署的 Activation Key 原样保留；首次升级只自动补齐缺失的 Package/Notification Key，不替换已有合法密钥。
- `GET /api/v1/public-key` 同时返回三类公钥，并保留旧 `public_key` 激活公钥别名以兼容旧客户端。
- 产品安装身份使用服务器本地 Ed25519 密钥对；Installation ID 由安装公钥指纹生成。
- 安装解锁、刷新和产品迁机使用一次性 Challenge Proof，防止复制 Installation ID 或重放签名。
- 客户产品迁机使用短期一次性 `PMG_` Grant；新实例接管后旧安装身份与旧 Activation 进入 Fenced，禁止双活。
- 免费版、付费版和历史兼容版能力写入签名 Activation Token，并由 SDK 服务端 Guard 执行，不能只依赖前端隐藏。

## 授权、工单与运营

- License Key 支持永久删除；删除同时清理关联激活、构建、工单和文件，失败项进入补偿清理任务。
- 永久删除后只保留不含 Key、域名、邮箱、IP 或 Installation ID 的匿名 Tombstone。
- 工单支持客户和管理员关闭、管理员重开、关闭原因、内部备注、附件和完整审计。
- 管理后台与客户打包中心继续按独立入口、会话和权限运行，前端页面拆分为显式 ES Module。
- 管理员可查看完整 Key，但查看动作单独鉴权并写审计；列表仍只返回脱敏信息。

## 控制中心服务器迁移

- 管理后台新增独立“系统迁移”功能；新服务器先安装同版本 APPGOG，再开启 15 分钟一次性接收并生成配对码。
- 迁移前核对源/目标版本、时间、磁盘、Docker、Compose 和 HTTPS。
- 最终一致性阶段源端进入短暂只读，创建完整加密备份并通过固定迁移收件箱传输。
- 迁移包使用 64 MiB 分块；每块校验 SHA-256，支持同序号重传，全部分块齐全后再校验整包 SHA-256。
- 目标服务器恢复前创建自己的回滚备份，恢复失败自动回滚；源服务器失败时自动恢复 Active。
- 所有权使用 generation 控制。目标健康接管后源端写入数据库和文件双重 Fenced 状态，普通重启不能绕过。
- 迁移完成后只需把原授权域名和打包域名的 DNS 指向新服务器；客户 Key、客户业务域名、Installation ID 和已签发公钥身份不变。
- 当前 SQLite 方案保证最终数据一致，但切换时存在短暂只读窗口，不承诺完全零停机。

## 在线更新与运维

- 修复在线更新助手在 `latest_version` 为空时生成 0 字节 `status.json` 的问题。
- 增加更新助手 `--healthcheck` 和独立诊断日志；核心服务健康时，不再因辅助助手异常误报整套部署失败。
- 运维入口保持原命令不变，内部拆分为 `scripts/lib/*`：平台识别、Docker 安装、Release 下载、DNS、备份、诊断和生命周期各自独立。
- 首装和升级继续使用同一条固定命令。新版本环境字段自动补齐，已有合法值不覆盖。
- 升级失败保留诊断日志、备份和旧健康版本，并自动恢复；支持流程中禁止删除数据卷或盲目更换密钥。

## 数据库变化

本版本只执行向前兼容、可重复运行的结构扩展，不删除旧表、旧列或业务数据。新增或扩展的领域包括：

- 三类签名身份与能力快照；
- 安装身份、一次性 Challenge 和产品迁机 Grant；
- License 永久删除、补偿清理和匿名 Tombstone；
- 工单关闭/重开状态与审计字段；
- `control_plane_identity` 和 `control_migrations` 控制中心迁移状态。

所有迁移在真实旧数据库回归测试中验证。已有管理员、密码、License Key、Activation、公告、设置、上传、成品、日志、备份和密钥必须保持不变。

## 升级方式

已有服务器执行管理菜单“安全更新最新版本”，或运行：

```sh
appgog update
```

也可以逐字重跑 README 中的固定一键安装命令。升级不需要 GitHub 私有 Token，也不需要重新输入 License Key。若正式附件、环境合同、签名或 SHA-256 任一不匹配，安装器会拒绝更新。
