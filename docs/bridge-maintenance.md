# 授权桥管理

适用：运营中心 1.2.43，修复接口要求授权桥 1.1.3。

## 操作

1. 进入系统运维 → 授权桥管理，填写目标 Xboard 的公开 HTTPS 根地址、后台安全路径标识、管理员邮箱和密码。
2. 连接后显示目标插件记录与运行进程共同确认的桥版本。连接最多 20 分钟，绑定当前管理员会话；密码提交即清空，远端 Token 不进入数据库、浏览器存储或日志。
3. 点击检查更新。中心从指定 GitHub 仓库 Latest 正式发布下载清单、签名和平台 ZIP，验证 Ed25519 与 SHA-256 后提取桥包。检查结果 10 分钟有效。失败、发布源落后、相同版本或过期时不允许升级。
4. 点击安全更新最新版本。通过 Xboard 官方插件上传接口执行升级，随后检查插件与进程版本一致、安装身份不变。新迁移更新宿主文件并请求进程重载。原授权、安装身份、主题配置继续保留。
5. 修复当前版本：调用已安装桥的管理员维护接口，恢复固定宿主注册、Guard 和管理脚本，刷新 PHP 缓存并请求 Octane 重载，然后核验版本与身份。此操作不是重复上传同版本 ZIP，不能恢复已删除的插件源码。旧桥必须先升级。

## 失败与恢复

- 首次未安装桥、插件已停用、站点无法登录或管理 API 不兼容时明确报错；不自动启用被停用的桥。
- 当前实现仅连接公开 HTTPS 标准 443 端口。拒绝内网/本机/保留地址、混合 DNS 解析与目标重定向；TLS 验证保持开启，连接固定到已校验 IP。
- 不支持用该页面修复 Xboard 无法启动的 500 错误；先使用原生后台、容器日志与文件备份恢复。
- 插件升级依赖 Xboard 官方更新行为，不宣称拥有平台 Docker 更新的自动回滚能力。上传失败或连接中断后，目标状态可能已改变；重新检查实际版本再决定下一步，禁止自动重复上传。
- 独立任务编号、阶段、错误码和日志存入 Operations 设置，状态变化与审计在同一事务中保存。重启后未完成任务标记结果未知，不自动重放。正式部署仅一个 license-api 写进程，每次只能执行一个授权桥任务。
- 页面当前显示的是所连接站点的实际运行版本，不是中心内置桥版本。更新中心不会自动修改客户服务器；需要明确连接并触发。

## 回归

自动测试覆盖旧宿主文件升级/重复迁移的数据保留、维护接口的停用拒绝与失败、鉴权/权限/CSRF、错误/过期/落后发布源、签名与哈希、并发操作拒绝、进程中断和身份变化，以及实际 UI 的按钮、凭证清空、错误禁用与窄屏布局。浏览器回归使用隔离模拟目标；真实客户站点升级验收须单独记录，不将模拟测试称为线上成功。
