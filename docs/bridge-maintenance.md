# 授权桥组件更新

适用：运营中心 1.2.47；本版本内置授权桥 1.1.5。

## 固定操作

进入系统运维 → 授权桥更新。页面直接显示当前打包用组件版本，只提供三个操作：

1. **检查版本**：从固定仓库 Jerry2586/Universal-authorization 的 GitHub 正式发布读取清单、签名和平台 ZIP，验证 Ed25519 与 SHA-256 后提取授权桥。检查结果 10 分钟有效；失败、相同版本、源版本落后或结果过期均不开放更新。
2. **更新**：重新复核已检查的正式版本，将签名证据写入固定持久目录并原子切换。后续新打包任务和独立 Worker 使用该组件。
3. **修复**：重新下载当前选中组件对应的正式发布版本，验签后重新保存。组件损坏但索引可读时仍可修复；禁止借修复降级。内置开发版本尚未正式发布时，下载失败会明确显示，不伪报修复成功。

无站点地址、后台路径、管理员账号密码输入，无连接或断开步骤。旧版远程站点连接接口已移除。

## 生效与恢复边界

- 页面维护中心打包组件，**不代表客户服务器实际运行桥版本**。已下载的旧包和已部署的插件不会被改写。客户需安装新构建的主题/桥后才获得新脚本。
- 存储目录固定为 ARTIFACT_ROOT/bridge-distribution，包含已验证正式发布证据和 active.json 索引，随原业务制品备份保留。校验未通过不切换，未完成写入不影响原选中组件；组件损坏时禁止继续打包。
- 系统升级自带更高桥版本时优先采用更高内置版本，避免被旧覆盖组件锁定。不会重签客户 Key 或修改安装身份。
- 独立 Worker 只接受包签名公钥验证通过、绑定当前构建与签发者且未过期的桥快照，不需要 Release 私钥、客户管理员凭证或中心签名私钥。
- 任务及状态保存于 Operations，自带独立操作编号与日志；状态及审计同事务。单 license-api 写进程串行执行；重启中断不会自动重复更新。
- 此页面不修复客户 Xboard 的启动 500。客户站点恢复和插件升级属于另一条操作链路，需要单独验收。

## 回归

覆盖签名/哈希、过期与落后源、同版本修复、损坏文件恢复、原子选择、进程中断、任务绑定、独立 Worker、管理员权限和 CSRF；浏览器检查版本/更新/修复、失败禁用和窄屏布局。桥迁移检查旧持久脚本刷新、原安装身份与授权数据保留。浏览器用隔离数据，不将本地通过称为线上完成。
