# 本地安全中心：事故处置与验收边界

本功能为候选开发，正式安装入口只有在新版本按发布合同交付后才包含这些功能。每台业务 Linux 主机独立安装本机检测代理与 root 事故执行器；本地运行不依赖云端。云端建设按本地完成之后的顺序继续。

## 部署、入口和权限

- 同机 all：一个 APPGOG 容器包含授权与打包，隔离会同时暂停两者。
- 分机 license/build：每机独立扫描和处置，只控制本机唯一归属的 APPGOG 容器。不能借授权身份执行打包主机命令。
- 后台安全页提供状态、手工扫描、异常提示和最近八条状态变化。本机保留最多六十四条检测事件。结果过期、不可用、未完成或字段不完整时不能显示为健康。
- Linux 管理入口为 sudo appgog，菜单 17 管理本地检查，子菜单 10 打开独立事故中心。
- 事故发生后，即使业务程序文件损坏，也可直接运行 sudo /usr/local/sbin/appgog-security-response menu。该控制器安装在 /usr/local/lib/appgog-security，不从当前业务发布目录加载程序。
- 后台固定 Unix Socket 只允许 status/scan，不提供容器、删除文件、执行命令或解除隔离的接口。事故执行器只接受本机 root 的固定动作；没有远程万能解锁密码。

## 检测范围

程序完整性与病毒检查覆盖固定发布清单：apps、packages、scripts 以及 package.json、锁文件、Dockerfile、三种 Compose、三种 Caddyfile、环境示例和安装入口。主机配置基线记录固定账户、SSH、sudo、cron、systemd、Docker 和防火墙配置。另检查固定敏感文件的所有者与权限、有效 SSH 配置、TCP/TCP6 监听和 APPGOG 容器运行合同。

病毒扫描不是整盘扫描：node_modules、业务数据库、上传、构建成品、宿主其他目录、进程内存和内核威胁不在该扫描范围。合法环境变更也会导致配置告警，需要独立核对后批准。首次建立基线要求来源可信；在疑似失守的主机上重新批准现状不能证明干净。

ClamAV 缺失、特征库过期或无效、扫描异常、超限或文件在扫描中变化时，病毒结果保持未知。安装会补齐发行版 ClamAV 及更新服务；软件源失败时业务仍保留运行，查杀明确不可用，可从菜单重试。特征扫描阳性和文件哈希匹配都不构成“没有入侵”的保证。

Cloudflare 账号、DNS、Workers、规则和 API 凭据变更尚无持续审计实现。文件检查通过不能判断 CF 账号安全。宿主 root 或 Docker 管理权限彻底失守时，同机软件、基线与镜像均可能被改，须通过可信带外控制台保存证据并在干净主机重建。

## 默认告警与受控隔离

默认模式 alert-only，不会因单项哈希偏移、未知结果或云端失联停业务。root 明确开启 auto-contain 后，每五分钟评估一次；病毒阳性与程序基线偏移同时出现才自动隔离。管理员也可在事故菜单手工确认隔离。

隔离前核验完整容器 ID、唯一 Compose project/service 和安装目录归属，保存固定脱敏证据，不保存 inspect 环境变量、密钥正文或任意日志。随后把重启策略设为 no，停止该容器，核验确已停止。失败时记录 containment_failed 并继续禁止普通启动。重试只操作原容器；容器被替换时拒绝自动继续。

不删除容器、镜像、卷、客户数据或旧发布目录。归属不清或同一项目多容器时拒绝操作。活动事故阻止受支持入口的启动、重启、安装、升级、恢复和安全服务卸载，防止覆盖现场；root 绕过受支持入口直接操作 Docker 仍不在可防止的边界内。

## 离线可信源码修复

提前把同一正式版本 ZIP、release-manifest.json 与其 .sig 放入 root 私有目录。使用事故菜单导入到本机 trusted-releases 缓存。独立发布公钥固定在执行器目录；安装发现公钥改变会拒绝，不能通过普通升级静默替换信任根。

导入时验证 Ed25519 清单签名、schema/product/精确版本、标准 ZIP 名称及 SHA-256；拒绝同版本不同内容替换。ZIP 校验限制 128 MiB 压缩包、8192 项、单文件 8 MiB、总展开 256 MiB，拒绝穿越、反斜杠、重复项、特殊文件、符号链接、加密项和非发布根条目。

修复只允许独立配置记载的当前版本、原容器已停止且事故隔离仍有效。程序解压到新 releases 目录，原子切换 current 并重建程序基线；保留旧现场及 shared/.env，不执行包中脚本。失败回退链接与程序基线，保留分阶段文件用于调查。

源码修复不修 Docker 镜像、数据库、密钥、客户包、可写卷或主机配置，也不会自动启动业务。自动重建容器与整体主机自愈尚未实现。对新正式版本的升级仍走正常签名发布流程，不能借修复隐式升级或降级。

## 恢复条件

事故前应独立核验正在运行的可信版本及完整镜像 ID，使用事故菜单固定镜像和程序/主机基线。这是本机 root 批准记录，不是发布方镜像签名或硬件根信任。

解除隔离须同时满足：

1. root 人工复核可写业务数据、密钥、客户文件和事故范围，并输入 APPROVE-DATA-AND-RESUME。
2. 容器仍为事故前同一个完整 ID，镜像 ID 与事故前批准记录一致，程序及主机基线 pin 未被事故后批准覆盖。
3. 新鲜程序、主机配置、权限与病毒检查全部为 ok；未知不放行。
4. 原容器启动后健康，重新扫描仍通过且运行合同有效，才恢复原重启策略并记录 released。

任何失败重新停止容器；再次停止失败保留 containment_failed，事故守卫继续生效。没有事故前批准、可信病毒结论或业务数据审核时保持隔离，不能重新批准可疑基线来强行解封。检测到真实感染或宿主失守时，优先选择干净主机与独立核验备份恢复。

## 安装事务与保留状态

安装更新检测执行器、固定配置、独立公钥、服务和定时器。激活失败尝试恢复此前执行器/服务文件、检测服务启用状态，以及事故定时器分别的启用与运行状态。无法停止运行中的服务时不覆盖执行器，保留事务目录以便带外处理。环境补齐、专用安全组、GID 配置、运行目录与证据不会回退为安装前全状态。

卸载先验证归属并停止检测与事故定时器，不移除独立配置、公钥、事故证据、基线、历史与专用组。活动事故拒绝卸载；重装沿用安全组权限和原有基线，不自动接受未知环境变更。

## 验收分层

Windows Python/Node 测试包含固定动作、归属、证据脱敏、恢复失败、双证据策略和安全 ZIP 边界，其中 Docker 与扫描结果用明确 mock 构造，不能作为 Linux 演练证据。

独立 Ubuntu CI 运行真实 systemd、Unix Socket、受权/未受权非 root 容器、ClamAV 自定义测试特征、安装失败回滚、定时器状态、独立公钥拒换、保留卸载与重装。另使用真实 Docker 容器及一次性测试 Ed25519 密钥演练隔离、负面恢复和离线程序修复。测试密钥只在测试进程指定，不替换安装公钥；CI 清理专用标记也不代表业务恢复成功。

官方新鲜病毒特征库下的完整恢复成功、生产双/三机联通、CF 持续审计、不可变异地备份、整机失守重建与 RPO/RTO 演练需各自真实记录。没有这些证据不宣称整体生产验收完成或杜绝入侵。

卸载保留事故历史。事故已解除且记录完整、归属正确时，重复卸载或重装会保留原记录与证据；执行器已经卸载时，由安装器只读校验该历史。活动事故、无效记录、外部安装目录记录、符号链接及不安全权限均拒绝卸载或重装，不能靠删除执行器绕过事故保护。
