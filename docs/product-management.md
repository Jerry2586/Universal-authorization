# 产品管理边界

产品管理入口位于授权中心的“产品交付 → 产品管理”。产品负责名称、固定标识与归档状态；套餐、授权状态、版本发布和构建任务继续由各自模块负责。

## 管理方式

- 创建产品：名称 1–80 字符；标识为字母开头、最多 64 位的小写字母、数字或短横线。标识创建后不可修改。
- 编辑：修改产品名称，原产品 ID、授权关系和版本关系保持不变。
- 归档：禁止新签发授权和新发布版本；已有 Key、激活、更新权益、构建记录保持原规则，不隐式撤销授权。已有客户仍可按其权益使用历史可用版本。
- 恢复：重新允许新签发与新发布。
- 不提供产品硬删除；需要撤销客户使用权限，应在授权管理中暂停、撤销或删除对应授权。
- 签发授权与上传版本必须选择已创建且启用的产品。默认产品仍为 APPGOG；其他产品不会与 APPGOG 共用版本目录。
- 产品管理不扩展打包器支持的源码类型；当前交付仍须满足 Xboard 主题包合同。

## 权限及服务边界

- 产品列表使用 product.view；创建、编辑、归档、恢复使用 product.manage，写请求必须验证管理员会话及 CSRF。
- 平台所有者、超级管理员和版本管理员可以管理产品；授权运营、客服、审计员只读。
- 管理页面不能通过签发授权或发布版本接口隐式创建产品。旧内部 /api/v1 兼容调用与初始化仍可使用原有 ensureProduct 语义。
- Product Management Service 通过最小 Repository Port 写 products；产品修改与审计在同一数据库事务内提交，审计失败则回滚。
- 产品列表和全产品版本列表为只读投影，授权与激活状态仍由原模块判断。
- 本次复用已有 products 表，不删除、重建数据，不改已有 Key、Installation ID、密钥或套餐快照。

## 验证

- HTTP 回归覆盖权限、CSRF、标识不可更改、未知产品拒绝、同版本跨产品隔离、归档后的授权刷新、恢复、旧库再次启动、审计失败回滚。
- scripts/verify-product-management-ui.cjs 在独立本地数据库测试创建、编辑、归档、恢复、按所选产品签发授权及上传真实 ZIP、版本筛选，以及桌面/390px 页面。
- 该浏览器测试与线上安装验收相互独立，不能代替 appgog.com 实际主题及插件生命周期验收。
