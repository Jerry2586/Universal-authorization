## 已确认故障与修复

1. 本机仍运行 1.2.10 旧服务，只监听 8787；8788 无服务，管理端指向打包中心的链接不可用。代码更新不会自动替换已有进程。
2. 独立打包中心漏发 customer-portal.js 及递归依赖模块，浏览器无法注册登录事件。已补齐客户静态资源白名单，管理端模块仍不对外开放。
3. 代理未完整传递客户端 IP、请求编号和错误上下文。已共用 core 中的解析规则，补齐请求/响应头、错误关联和上游超时处理。
4. 打包中心健康检查未反映静态资源、上游或节点凭证故障。已增加真实就绪检查，异常返回 503。
5. 启动角色与默认公开地址可能与实际端口不一致。已固定专用启动入口角色、使默认地址跟随角色和端口，保留显式配置；npm start 默认启动拆分服务，启动前拒绝端口冲突。
