# 客户主题包内容签名合同

## 信任与交付边界

新构建采用两份用途不同的包签名：

- `package_manifest_token`：授权中心在领取构建任务时签发包身份，包含 `content_signature_required: true`。
- `content_signature`：授权中心在确认构建完成时签发，类型固定 `package-content-v1`，绑定签发方、Build ID、Package ID 和最终清单摘要。

Worker 只取得构建凭据和验签公钥，不能取得包签名私钥。最终文件签名使用现有 Package 签名用途，不使用 Activation、Notification 或发布附件签名密钥代替。

`completeBuild` 先核验任务租约、构建身份、输入 ZIP 哈希、Package Proof、文件摘要/HMAC 和 Install Key，再签名、写入最终 ZIP、记录最终 ZIP 哈希并完成队列任务。下载票据及下载响应必须对应加签后的 ZIP，不再使用 Worker 草稿哈希。未完成任务的草稿不开放客户下载；写入失败或队列提交失败不能返回构建成功。

## 内容摘要

内容签名覆盖整个 `build.json` 的规范化 JSON，唯一排除顶层 `content_signature` 本身。包含身份签名、公钥、服务地址、保护配置、生命周期、创建时间、完整性摘要及逐文件列表。JSON 对象属性递归按键排序，数组保持顺序；Node、浏览器和 PHP 对同一内容计算 SHA-256。

逐文件列表覆盖业务 JS/CSS、页面、授权运行时、AES 身份文件和内置桥 ZIP。清单文件不进入其自身逐文件列表，避免自引用。普通哈希和 HMAC 保留，但不再充当唯一的防篡改信任依据。

## 消费与兼容

- 成品校验器默认要求新包具备有效内容签名；仅中心完成构建的内部路径可临时校验未签名草稿，然后立即加签并再次验证。
- 浏览器从签名包身份读取是否必须验签，不能由未签名清单开关降级。内容签名失败时保持锁定，禁止注册、插件上传和激活等安装写操作。
- 桥在上传登记、受保护页面访问、运行状态读取、挑战签名和激活刷新时验证相应完整性边界。新包对安装源目录和实际公开的 `public/theme/<theme>` 副本分别验证全部已列文件摘要、清单一致性，并拒绝额外注入的 HTML、JS、PHP 文件。首次上传在复制前验证源目录、复制后验证公开副本；运行状态与授权保护请求不能仅验证源目录。
- 初次登记的公钥信任来自管理员认可的安装渠道（首次信任/TOFU），不能声称从一个任意来源 ZIP 自带的公钥就能证明厂商身份。既有登记不得由后续包静默替换公钥；公钥轮换需要独立受控恢复流程。
- 无 `content_signature_required` 声明且没有内容签名的旧身份凭证继续走旧包兼容路径；不得把旧包已兼容误称为旧包已获得新防篡改能力。要取得本轮保护须重新构建客户包。
- 既有固定 Key、一次性 Install Key、60 分钟安装窗口、服务器身份、暂停/撤销和免费/付费权益不改变。

## 授权桥与生成脚本

授权桥本轮升至 1.1.6，新增唯一迁移 `2026_09_29_000013_content_signature`，更新持久 Guard 并安排 PHP 运行时重载，保留安装身份、激活记录及原 bootstrap 备份。

源业务 JS 的保护保持原有 Terser＋混淆流程。生成的授权运行时在插入 ZIP 前追加混淆；桥前端 JS 在桥 ZIP 生成前追加混淆。转换失败停止交付。公开浏览器 API 标识及部分正则表达式仍可能可读，不宣称所有字符串均不可读。

默认移除开发用 `preview-panel.html`。除三个主要入口外，完整 HTML 文档或含脚本的 HTML/HTM 文件也加入运行时注入；没有脚本的 HTML 片段保留为资源。PHP 桥保持可执行源码，ZIP 保持 Xboard 可解压格式。

## 实际安全边界

包内 proof 是包级凭据，仍可由控制执行环境的一方取得；AES 用于包身份数据，不能宣称整个业务源码由不可取得密钥加密。签名可让受信任的校验器拒绝修改后的文件，不阻止拥有服务器 root 权限的人修改校验器本身。

不承诺百分百防逆向。回归目标是：已加签内容被改后不能靠重算 HMAC 放行；删除内容签名、换公钥、改变域名/桥摘要等行为被拒绝；正常旧包、两阶段激活、升级与原生后台恢复保持可用。

## 本轮独立复核

独立审查发现初版仅验证主题源目录、遗漏公开副本。本轮已补双目录校验，并以仅修改公开 JS、仅在公开目录新增 JS 的 PHP 回归证明确实拒绝；恢复原文件后重新通过。浏览器静态页面仍由宿主 Web 服务器直接提供，签名校验不等于阻止所有未校验脚本在浏览器执行；PHP授权与配置接口会拒绝篡改副本，不能将该边界夸大为浏览器沙箱或 root 防护。

## 性能验收状态（发布阻断）

2026-09-29 在本机 Windows PHP 对真实513文件包做双目录验签，清除PHP路径/状态缓存后的连续5次耗时为1050.22、809.62、308.25、1105.36、1318.87毫秒。该测量只针对校验函数，不等于生产Linux页面响应时间，但已足以阻止“无感加载已验收”的声明。

当前实现逐文件检查且不复用未经确认的激活标记，正确性回归通过；性能尚未通过生产同类Linux环境压测。不得直接加入永久缓存或缓存授权结论以掩盖成本。下一步应在Linux PHP运行环境分别测量磁盘遍历、文件哈希和签名成本，并验证请求去重/校验编排优化。优化必须保留只修改公开副本也能被拒绝、原生后台修复入口可用、暂停撤销不受完整性缓存影响等回归。

当前工作环境未发现可调用Docker命令，尚未取得真实Linux性能数据。正式版本发布和线上升级保持未执行。
